# Сайт села

[English](site.md) · **Русский**

`verso site` пишет записи села статическим сайтом: каждая книга показана как документ, с которого
она прочитана, запись за записью, с указателем имён и поиском. Это простые файлы — HTML, один
лист стилей, один скрипт поиска, — которые отдаёт любой хостинг статических страниц, а браузер
открывает с диска (`verso.ru.site`).

```sh
verso site --village V --out _site
    [--records DIR] [--docs DIR] [--title T] [--summary S]
    [--repo-url U] [--site-url U] [--revision R]
    [--license NAME --license-url U] [--strict]
```

`--out` — новый или пустой каталог. Выход 0; 1 при `--strict`, если какой-то файл DSL не загрузился
или на собранном сайте есть битая ссылка; 2 — отказ: каталог не пуст, две книги дают один адрес,
текст ссылается в никуда.

## Что показано

Записи строятся так же, как их строит `verso export-records`, — или читаются из выгрузки,
`--records`, — и рисуются по схеме интерфейса `ui-v1.json`: даты вида, его люди в порядке граф
книги, члены двора таблицей, карточка внешнего каталога со ссылкой на неё. Поэтому сайт показывает
то, что лежит в [JSON записей](records-json.ru.md), а поле, которое получил словарь, попадает на
страницу само.

- **Написанное в записи — текст; выведенное библиотекой стоит рядом и помечено.** Имя показано в
  орфографии источника; современная форма, фамилия ребёнка по отцу, сословие, перенесённое с
  родителя, набраны другим начертанием. То, что умолчания книги дают каждой статье — приход как
  место, «крестьянин», — сказано один раз, в шапке книги.
- **Невычитанная запись показана и помечена.** Запись с `reviewed=False` несёт пометку, а её книга
  и лицевая страница их считают ([храповик вычитки](review-ratchet.ru.md)). Пометка — вердикт выгрузки
  о построенной записи (`review`), а не наличие ключа: лист, отпущенный внутри удержанного набора,
  вычитан, его соседи — нет. Узел без вердикта получает отказ.
- **Книга ЗАГС так и названа**: её вторая дата — регистрация.
- **Не показаны**: комментарии `#` из DSL (`note`), путь к скану (`scan_file`), метки цели и
  ничего от Terraform или дерева — сайт читает записи, а не то, что из них сделано. В одного
  человека он тоже никого не сводит: указатель имён перечисляет упоминания, по персоне на запись.

## Страницы и их адреса

| Страница | Адрес |
|---|---|
| лицевая страница | `/` |
| книги по архиву, фонду и делу | `books/` |
| книга и её записи | `books/<village>/<fund>-<inventory>-<case>[_<part>]/[<year>/]<kind>/` |
| карточки внешнего каталога | `cards/<village>/<kind>/` |
| годы и книги одного года | `years/`, `years/<year>/` |
| фамилии и упоминания одной | `names/`, `names/<surname>/` |
| записанные без фамилии, по отчеству | `patronymics/`, `patronymics/<patronymic>/` |
| поиск и его указатель | `search/`, `search/index.json` |
| тексты о селе | `about/`, `<page>/` |

Адрес записи — правило `r1` её идентификатора: страница книги, по которой она цитируется, то есть
идентификатор без токена, и токен как якорь (`…/1900/birth/#f4`, `#m12~2`, `#m_1`). Запись, которая
называет свой шифр, стоит на странице той книги. Сегменты пути книги — латиница, по транслитерации
адресов рабочего пространства (`[translit] address`), чей профиль заморожен; страница имён названа
самим именем. Поэтому адрес меняется вместе с идентификатором — когда исправлен номер, пол или
шифр, — и никогда от пересборки: те же записи дают те же байты. Две книги, чьи идентификаторы дают
один путь, получают отказ с именами обеих.

Все ссылки относительные, так что сайт одинаково открывается из пути проекта на хостинге, со своего
домена и из каталога. `--site-url` добавляет то, чему нужен адрес: `sitemap.xml`, канонические
ссылки и ссылки `404.html`. С чужого хоста не загружается ничего: ни шрифта, ни скрипта, ни
счётчика.

## Как найти человека

Без JavaScript: указатель фамилий, на каждую — страница со всеми её упоминаниями по порядку лет;
женская форма стоит вместе с мужской, если в корпусе есть обе. Тех, кого источник пишет без
фамилии, находят по отчеству в форме книги, а у записанных одним именем — своя страница.

С ним: поиск один раз читает `search/index.json` и ищет каждое слово запроса в современной и в
исходной форме, приведённых к одному виду — строчные буквы, буквы, которые убрала реформа 1918
года, заменены современными, твёрдого знака в конце слова нет, — так что «Феодор» находит
«Ѳеодоръ».

## Тексты о селе

`<village>/docs/*.md` (`--docs`) становятся страницами: `README.md` — оглавление (`about/`), всякий
другой файл — страница под своим именем, в том порядке, в каком на них ссылается оглавление. Ссылка
на другую страницу текстов ведёт на эту страницу; ссылка на файл DSL — на его книгу на сайте;
любая другая ссылка внутрь рабочего пространства — в репозиторий (`--repo-url`), а без него
получает отказ. Ссылка за пределы рабочего пространства, ссылка в никуда и картинка получают отказ;
HTML в тексте показан как текст. Абзац о селе на лицевой странице — `--summary`, иначе первый абзац
`history.md`.

Идентификатор заголовка — как на GitHub: его текст строчными буквами, всё, кроме букв, цифр, `_`, `-` и
пробелов, отброшено, каждый пробел — дефис, повторный заголовок получает номер (`-1`), — так что ссылка
на раздел (`places.md#храмы`) читается одинаково в репозитории и на сайте; ссылка на раздел, которого
на странице нет, роняет сборку с `--strict`. Страница не может занять имя, которое сайт держит за
собой: `assets`, `books`, `cards`, `years`, `names`, `patronymics`, `search`, `about`
(`verso.ru.site.RESERVED`).

Markdown читает markdown-it-py (CommonMark и таблицы) — экстра `verso-ru[site]`; селу без текстов она
не нужна.

## На GitHub Pages

Репозиторий с DSL села собирает сайт на каждый push и выкладывает его с основной ветки; pull
request получает ту же сборку артефактом.

```yaml
jobs:
  site:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: '3.14'
      - run: pip install 'verso-ru[site]'
      - run: verso site --village Горюхино --out _site --strict
      - uses: actions/upload-pages-artifact@v5.0.0
        with:
          path: _site
  deploy:
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    needs: site
    runs-on: ubuntu-latest
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
    steps:
      - uses: actions/deploy-pages@v5.0.1
```

Pages репозитория настраиваются на сборку из GitHub Actions (Settings → Pages → Source) до первого
push: токен workflow включить их не может.

## В Python

```python
from verso.ru.site import build

built = build(files, out=out, village="Горюхино", site_url="https://example.org/gorjuhino/")
built.pages, built.bytes, built.unreviewed     # что записано
built.problems                                 # битые ссылки и якоря, дважды встреченный id: пусто, когда всё цело
```

`files` — узлы файлов records-v1 одного села, в любом порядке. `verso.ru.site.check.verify(out)`
так же судит любой собранный каталог.
