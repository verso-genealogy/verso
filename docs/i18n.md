# The interface's language

verso speaks to a person — an error, a command's help, a linter's finding — through catalogs of
messages, one per language. English is the source language; Russian is a translation. What verso
*generates* — a Geni profile's prose, a Familio CSV, a timeline — is not the interface and never
follows its language.

## Which language

In this order:

1. `verso --lang LANG <command>` — for that command;
2. `VERSO_LANG`, set per command;
3. `[i18n] locale` in `verso.toml` (schema 5); a file of schema 4 or older speaks Russian, as the
   library did before the catalogs, and one of schema 5 without the key speaks English;
4. English.

The system's `LANG` and `LC_*` say nothing. Without a workspace — an error that says none was
found — the language is `VERSO_LANG`, else English. A language nobody ships is refused with the
list of languages.

```toml
schema = 5

[i18n]
locale = "ru"
packs = []          # language packs to enable, by name
```

## Catalogs

Each distribution ships its catalogs as package data, `<package>/locales/<lang>.toml`:

```toml
schema = 1
untranslated = []              # in a translation: the keys still printed in English

[workspace]
not_found = "no workspace found from {start}"

[plugins.count]                # a plural: a table of CLDR categories, chosen by `count`
one = "{count} plugin"
other = "{count} plugins"
```

- A key is `<module>.<what>` within its package (`workspace.not_found`); a linter's is its code and
  variant (`CPL002.no_father`).
- A parameter is `{name}`; a literal brace is `{{` or `}}`.
- A key the language lacks falls back to English; one English lacks, a catalog that does not read
  or a parameter missing print `key {params}`. Rendering never raises: the error a message was
  raised for is never hidden by its message.
- Code calls `t("key", name=value)` from its package's `messages` module. It returns a `Message`,
  whose text is put together when it is read, in the language of that moment.

The keys of the catalogs and their parameters are public: a translation is written against them.

## Language packs

A language verso does not ship comes as a distribution of its own: an entry point of the group
`verso.locales` gives a `verso.core.i18n.LocalePack` — its name, its language, a catalog for each
package (`"<import package>:<path>"`), and its plural rule — and a workspace enables it by name in
`[i18n] packs`. A pack cannot replace a language a package already ships. A pack that is not
installed, or would replace a shipped language, and a `locale` nobody speaks are refused when
`verso.toml` is read; until then a message falls back to English, and the languages a package
ships never consult a pack. `VERSO_LANG` or `--lang` naming a language nobody speaks is refused
when `verso` starts.

## What is not translated

The books' text has four kinds, and only the first is the interface's:

- **messages** to a person — through the catalogs;
- **generated content** — Geni's prose and its locale keys, the Familio CSV and справочник, the
  timeline: the plugin's content profile, frozen, whatever the interface speaks;
- **the sources' vocabulary** — statuses, causes of death, the saints' calendar, the old
  orthography: the plugin's, in the books' language;
- **the books' domain** — sex, the leaf's label, the estates: the plugin's, not the core's.
