## Что публично

Корпусу, который пишет не автор библиотеки, она обещает то, на что такой корпус опирается:

| Поверхность | Где зафиксирована |
|---|---|
| фасад DSL — `verso.ru.dsl` и три его каталога | `packages/verso-ru/src/verso/ru/dsl/api-v1.json`, `DSL_API` ([справочник](reference/dsl-api.md)) |
| статусы корпуса как `<the corpus directory>.statuses` | [рабочее пространство](workspace.ru.md) |
| схема JSON записей и её правило идентификаторов `r1` | `records-v1.json` ([JSON записей](records-json.ru.md)) |
| схема страницы вычитки и ключи её подписей (`ui.*` в каталогах `verso.ru`) | `ui-v1.json` ([JSON записей](records-json.ru.md#схема-интерфейса)) |
| команды `verso`, их флаги и коды выхода | [справочник](reference/commands.md) |

| строка базы рекомендательных находок (baseline) (v2: `# baseline v2`, ключ — файл, код, параметры) | [справочник](reference/linters.md) |

## Версии

Пока версия 0.x, **минорная версия может ломать совместимость**. Публичное имя, которое будет
удалено или переименовано, живёт одну минорную версию рядом со своим преемником и предупреждает
(`DeprecationWarning`), прежде чем исчезнуть. Запускайте проверки корпуса с
`PYTHONWARNINGS=error::DeprecationWarning`, чтобы узнать об уходящем имени, пока оно ещё работает;
предупреждение сторонней библиотеки пропускайте только по её модулю
(`ignore::DeprecationWarning:<module>`), с причиной рядом.

Правило действует с **0.1.0**, первого релиза этого репозитория (2026-10-22): то, что 0.1.0 делает
публичным, — база, с которой сравнивается каждая следующая версия. Релиз — это тег `vX.Y.Z`,
называющий одну версию обоих дистрибутивов; между тегами в `main` лежит `.dev0` следующей версии, а
[CHANGELOG.md](../CHANGELOG.md) говорит, что изменил каждый из них.

## Схема рабочего пространства

`verso.toml` называет свою схему, и файл любой более старой схемы читается так же, как раньше: каждая
схема только добавляет ключи (их перечисляет [справочник](reference/workspace-keys.md)). Схема 6
меняет настройку словаря имён:

- **схема ≤ 5** — `[names] dir` называет старые таблицы (`names.csv`, `names_ignore.csv`,
  `patronymics_ignore.csv`), которые читаются как один слой, под которым ничего нет: имя, которого
  таблица не знает, остаётся неизвестным, что бы ни лежало в поставляемом базовом словаре. Файл
  схемы 5 отвечает как прежде;
- **схема 6** — по умолчанию поставляемый базовый словарь (`[names] base = "ru"`), над ним слои
  `[names] layers`. Схема 6 отвергает `[names] dir` (ключ схемы 5: файл, переходящий на схему 6,
  записывает свой старый каталог как слой), а файл схемы ≤ 5 отвергает `base`, `layers` и
  `writable`.

**`names.csv` как слой — до 0.2.** Каталог из `[names] layers`, где лежит старый `names.csv` вместо
`names.tsv`, читается как старая таблица, с `DeprecationWarning`. В 0.2 слой — это только три
TSV-файла; `verso names layer-diff` пишет их из старой таблицы
([рабочее пространство](workspace.ru.md#словарь-имён)).

## Версия DSL

`DSL_API` растёт, только когда имя фасада исчезает или переименовывается; новый именованный аргумент
со значением по умолчанию совместим и оставляет его как есть. Файл более старого DSL сообщает об
этом при загрузке, а `verso upgrade-dsl` его переписывает ([DSL](dsl.ru.md)).

## Выходные данные, которые служат адресами

Некоторые выходные данные служат идентификаторами в другой системе, и verso держит их неизменными по
байтам от версии к версии:

- res_name — адрес Terraform: профиль транслитерации `ru-v1` заморожен своим хешем, и новое
  написание было бы новым профилем; `ru-v2`, профиль имён, которые читает человек, заморожен так же;
- идентификатор записи (`r1`) называет её в JSON записей, слое фактов и ссылках;
- текст документа на Geni заменяется, когда меняется, поэтому смена вывода — это пометка в
  примечаниях к релизу.
